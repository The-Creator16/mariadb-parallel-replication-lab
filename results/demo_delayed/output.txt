==============================================================================
3. The accident
==============================================================================
[primary]> DROP TABLE shop.customers
[primary]> SELECT @@last_gtid
    0-1-20681
[replica]> SELECT COUNT(*) FROM information_schema.TABLES WHERE TABLE_SCHEMA='shop'
    0
  -> the normal replica applied the DROP within a second. The delayed one still has the table:
[delayed]> SELECT COUNT(*) FROM shop.customers
    5

==============================================================================
4. Find the statement in the binlog: GTID events make every transaction addressable
==============================================================================
$ mariadb-binlog /var/lib/mysql/mariadb-bin.000004 | grep -E 'GTID [0-9]+-|DROP TABLE'   (the match)
    #261122 22:30:13 server id 1  end_log_pos 834529 CRC32 0x42537c08 	GTID 0-1-20681 ddl thread_id=137
    DROP TABLE `shop`.`customers` /* generated by server */
  -> the DROP is GTID 0-1-20681; we want everything up to 0-1-20680 and nothing after.
