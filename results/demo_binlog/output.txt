  Read it top to bottom:
    GTID 0-1-N trans     the transaction's id (domain-server-sequence); 'trans' = transactional
    Annotate_rows / #Q>  the SQL statement that produced the row events below it. Without
                         binlog_annotate_row_events you would only see the rows.
    Table_map            which table the following row events refer to
    Update_rows + ###    the row images: what the replica will apply. The replica never
                         re-runs the UPDATE; it applies these before/after images.
    CRC32 0x...          every event header carries its checksum (binlog_checksum=CRC32)

5. Checksums: verify a binlog, then corrupt one byte of a copy
==============================================================================
$ docker compose exec primary sh -c "mariadb-binlog --verify-binlog-checksum /var/lib/mysql/mariadb-bin.000004 > /dev/null && echo 'all events: checksum OK'"
all events: checksum OK

  (copy of mariadb-bin.000004: one byte inside the Update_rows event at position 33458 changed)
$ docker compose exec primary sh -c "cp /var/lib/mysql/mariadb-bin.000004 /tmp/corrupt.bin && b=$(od -An -tu1 -j 33488 -N1 /tmp/corrupt.bin | tr -d ' ') && if [ "$b" = 0 ]; then v='\001'; else v='\000'; fi && printf "$v" | dd of=/tmp/corrupt.bin bs=1 seek=33488 conv=notrunc 2>/dev/null && echo "events in the copy, not verified: $(mariadb-binlog /tmp/corrupt.bin 2>/dev/null | grep -c '^# at')" && echo "events in the copy, verified:     $(mariadb-binlog --verify-binlog-checksum /tmp/corrupt.bin 2>/dev/null | grep -c '^# at')" && mariadb-binlog --verify-binlog-checksum /tmp/corrupt.bin > /dev/null 2>/tmp/err; echo "exit status: $?"; cat /tmp/err"
    events in the copy, not verified: 5647
    events in the copy, verified:     41
    exit status: 0
    ERROR: Error in Log_event::read_log_event(): 'Event crc check failed! Most likely there is event corruption.', data_len: 184, event_type: 24
  -> Without verification mariadb-binlog happily decodes the damaged event. With
     --verify-binlog-checksum it stops right before it and reports the CRC failure.
     Note the exit status: 0 (observed on 11.8.6). A script that checks a binlog
     must look at stderr, not at $?.

     A replica does not have that problem: with
     master_verify_checksum the primary checks events as it reads them from disk, the IO
     thread checks what arrives over the network, and slave_sql_verify_checksum makes the SQL
     thread check what it reads back from the relay log. A flipped bit stops replication with
     an error instead of being applied silently.
